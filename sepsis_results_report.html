1. Executive Summary

What was built, why it matters, and what the numbers say.

The Problem

Sepsis is a life-threatening response to infection that kills approximately 11 million people worldwide every year. In ICU settings, it develops over hours. A model that flags deterioration 6–12 hours before onset gives clinicians a critical intervention window — but the signal is buried in noisy hourly vitals with a 45:1 class imbalance (only 2.17% of records are septic).

The Approach

Instead of feeding raw vital signs into a black box, we engineer 70 temporal features — lags, trends, and rolling statistics — that capture how a patient is changing, not just their snapshot. These feed a regularized XGBoost model trained on a strict patient-wise split (no leakage).

The Headline Result

Temporal XGBoost achieves AUROC 0.800 (6h) and 0.804 (12h), beating every classical baseline. On AUPRC — the more informative metric under heavy imbalance — the model reaches 0.112 / 0.115 versus the baselines' 0.080–0.088. The improvement comes not from a fancier algorithm, but from feature engineering: an ablation study confirms 57.5% of model attribution comes from dynamic vitals.

Source, structure, and the constraints that shaped downstream design decisions.

Two Key Challenges

① Massive Class Imbalance (45:1)

Only 2.17% of rows carry a positive sepsis label. A naive model that predicts “no sepsis” every time would score 97.8% accuracy and catch zero septic patients. For this reason the project reports AUROC and AUPRC instead of accuracy, and used scale_pos_weight during training to compensate.

② Extreme Missingness in Lab Values

27 of the 44 raw columns are >80% missing, including every lab result (Lactate, Creatinine, WBC, Platelets, etc.) and the EtCO2 column (100% missing). Imputing these reliably is impossible, so they were dropped and only 16 reliable base columns (vitals + static context) were kept.

Design decision: Rather than impute unreliable labs, the pipeline invests in engineered temporal features from the 7 vitals that are reliably sampled: HR, O2Sat, Temp, SBP, MAP, DBP, Resp.

3. Methodology

From raw hourly vitals to a leakage-free, explainable early-warning model.

The Pipeline

Step 1 — Reframe the Target

Rather than predict “is this patient septic right now?”, the model predicts “will this patient become septic within the next 6 / 12 hours?” Only rows where the patient is currently non-septic are used — a currently septic row is not an early-warning sample.

→ 6h target positive rate: 1.15%
→ 12h target positive rate: 2.14%

Step 2 — Engineer 70 Temporal Features

For each of the 7 vitals, the pipeline adds:

  • Lags at 1h / 3h / 6h — value N hours ago
  • Changes at 1h / 3h / 6h — delta vs N hours ago
  • Rolling stats over a 3h window — mean, std, min, max

→ 84 total features (14 base + 70 temporal)

Leakage Prevention

  • Patient-wise split — the same patient never appears in both train and test.
  • Train-only imputation — medians computed on the training fold only.
  • Threshold tuning on validation — the test set is touched once, at the very end.
  • GroupKFold cross-validation for baselines — same leakage-safe protocol.

What the Baselines Reveal

Logistic Regression

Lowest AUROC (0.703). Its linear decision boundary cannot express “rising HR + falling BP + rising Resp together.” High recall (0.60) but very low precision (0.043).

Random Forest

Highest AUROC among baselines (0.739). Nonlinearity helps, but the model is still limited by seeing only raw snapshot values.

HistGradientBoosting

Tied on AUPRC (0.088). Catches only 37% of septic patients at the default threshold.

Key insight: All three baselines land in the AUROC 0.70–0.74 band and AUPRC 0.080–0.088. They plateau because raw snapshot values cannot express trajectory. A rising respiratory rate over 3 hours looks identical to a chronically high one. The temporal features close exactly this gap.

5. Temporal XGBoost — Final Model

The main contribution: 84 engineered features feeding a regularized gradient booster.

The final model is a regularized XGBoost classifier trained on the full 84-feature matrix (14 base + 70 temporal). Two variants were trained — one for the 6-hour horizon and one for the 12-hour horizon — with early stopping on validation PR-AUC.

⭐ Temporal XGBoost (12h) 0.8035 0.1153 0.6084 0.0727 0.1298 0.8277 0.1445
Why both horizons are useful: The 12h model has more positive examples to learn from (2.14% vs 1.15%), so it achieves slightly higher recall (0.608 vs 0.586). The 6h model fires later — closer to onset — so it produces fewer false alarms. A clinical deployment would use both: 12h for "watch this patient," 6h for "escalate now."

  • The AUPRC gain is the strongest signal: the model is measurably better at ranking rare positives correctly
Temporal XGBoost consistently outperforms all baselines, validating the value of engineered lag / rolling / trend features.

Why AUPRC Is the Decisive Metric

Under 45:1 imbalance, a model can look good on AUROC while being clinically useless. AUPRC directly measures how well the model identifies rare positives. A random classifier would score AUPRC ≈ 0.0217 (the base rate). The baselines reach 0.080–0.088 (3.7–4× random); Temporal XGBoost reaches 0.112–0.115 — roughly 5× better than random.

7. ROC Curves — Overall Discrimination

How well each model separates septic from non-septic across all thresholds.

ROC curves for Temporal XGBoost 6h (red) and 12h (amber) versus a random classifier (dashed diagonal).

How to Read a ROC Curve

Each point on the curve corresponds to a decision threshold. The x-axis is the False Positive Rate (1 − specificity) — the fraction of non-septic patients incorrectly flagged. The y-axis is the True Positive Rate (recall) — the fraction of septic patients correctly caught.

Interpretation of the Numbers

  • AUROC = 0.80 means: given one random septic patient and one random non-septic patient, the model correctly ranks the septic patient as higher risk 80% of the time.
  • AUROC = 0.50 would be a coin flip (the dashed diagonal).
  • AUROC > 0.80 is generally considered strong for clinical prediction tasks — the 12h model (0.804) crosses this line, and the 6h model (0.800) sits right at it.
Note on ROC limitations: ROC is threshold-agnostic and can be optimistic under heavy class imbalance. The next section (PR curves) is the more rigorous test.

8. Precision-Recall Curves

Under 45:1 class imbalance, this is the diagnostic that matters most.

PR curves for Temporal XGBoost 6h (red) and 12h (amber). Dotted lines are the prevalence baselines (2.17%).

How to Read a PR Curve

The x-axis is Recall — fraction of septic patients caught. The y-axis is Precision — fraction of alerts that are real. A perfect classifier sits in the top-right corner; a random classifier sits at the horizontal prevalence line.

Interpretation of the Numbers

  • AUPRC = 0.1122 (6h) — averaged across all thresholds, the model's precision is roughly 5× the base rate.
  • AUPRC = 0.1153 (12h) — slightly higher, consistent with the larger positive pool available for the 12h target.
  • A random classifier would score AUPRC = 0.0217. Both horizons are well above this floor.
Contextual benchmark: Published PhysioNet 2019 challenge entries using the full 40-feature set with clinical labs typically achieve AUROC in the 0.80–0.88 range. This model reaches 0.80 using only 7 vitals plus engineered temporal features — a competitive result given the much leaner input, and a clear improvement over all raw-feature baselines.

9. Threshold Analysis

Why 0.5 is the wrong default for this problem, and how the deployed threshold was chosen.

6-hour model: precision, recall, F1, accuracy vs threshold.
12-hour model: same analysis.

What These Figures Show

The default decision threshold (0.5) is designed for balanced problems. Because positives are rare here, the model outputs very few probabilities above 0.5. Lowering the threshold catches more septic patients at the cost of more false alarms. The graphs show how each metric responds.

MetricBehaviour as threshold ↓Reason
Recall Rises sharply Lower bar → more positive predictions → more sepsis caught.
Precision Falls steadily More true positives, but far more false positives as well.
F1 Peaks at an interior point Balances precision and recall; optimal point is where F1 is highest.
Accuracy Drops slowly Negatives dominate (98%), so calling more positives hurts this metric — but accuracy is misleading here.
Threshold selection protocol: Optimal thresholds were selected on the validation set by maximising F1, then frozen before evaluating on the test set. This avoids the common pitfall of tuning thresholds on test data.
Clinical consideration: In a live ICU deployment, the threshold would be selected jointly with clinicians based on their tolerance for false alarms vs missed cases. A hospital with more triage capacity would lower the threshold to catch more septic patients; a resource-constrained setting would raise it.

11. SHAP Explainability

A black box is unusable in medicine. SHAP shows exactly what drives each prediction.

SHAP (SHapley Additive exPlanations) is a game-theoretic method that assigns each feature a contribution value for every single prediction. The sum of contributions + base value = the model's log-odds output. This makes the model auditable: for any patient, the model can list exactly which vitals pushed risk up and which pushed it down.

SHAP summary (beeswarm) for the 6-hour model. Each dot is one patient. Features are ranked top-to-bottom by importance.

How to Read a SHAP Beeswarm Plot

  • y-axis: feature name, sorted by mean |SHAP| (most important at top).
  • x-axis: SHAP value — how much this feature pushed risk up (right) or down (left).
  • Colour: red = high feature value, blue = low feature value.
  • Each dot: one patient from the SHAP sample.

What the Plot Reveals

  • ICULOS (ICU length of stay) is the single strongest feature. Red dots (longer stays) cluster on the right — patients in ICU longer are more likely to develop sepsis. Clinically consistent.
  • Resp rolling statistics dominate the top 10. A rising respiratory rate over a 3-hour window is a well-known early sepsis signal.
  • SBP min/max over 3h — dropping BP is another classic indicator of deterioration.
  • Temp lag/rolling features — fever trajectory matters more than a single reading.
SHAP summary for the 12-hour model. The pattern is similar but with slightly different feature ordering — expected, since the 12h target is noisier.
Mean |SHAP| bar chart comparison between the 6h and 12h models.

Feature Group Breakdown

All 84 features were grouped into three categories and their mean |SHAP| contributions summed:

Feature GroupFeaturesSHAP ContributionShare

The most important scientific finding: 57.5% of the model's decision-making relies on dynamic vital trajectories — not static demographics and not just ICU length of stay. This validates the entire feature-engineering premise. Skipping temporal features would have forced the model to rely only on the 42.5% static context — much weaker signal.

12. Ablation Study

Four models trained on different feature subsets to prove the temporal features are doing real work.

Note on protocol: The ablation study below was run under a slightly different training / evaluation configuration than the two headline XGBoost models in Sections 5–6 (identical patient-wise splits, but a shallower single-fold configuration for speed). This is why the "Full (84 features)" row shows AUROC 0.765, while the frozen 6h/12h models — trained with early stopping and threshold tuning — reach 0.800 / 0.804. The relative rankings and conclusions are unaffected.
Feature Subset AUROC AUPRC Recall F1
Full (84 features) 0.76460.10790.48330.1416
Dynamic only (77) 0.68440.05350.45650.0834
Static + time only (7) 0.67910.07320.42340.0995
No ICULOS + no HospAdmTime 0.75870.10170.48190.1401

What Each Row Tells Us

Full model (84 features) — AUROC 0.765

The strongest configuration — all feature groups present.

Dynamic only (77 features) — AUROC 0.684

Removing static context (Age, Gender, ICU unit, ICULOS, HospAdmTime) drops AUROC by ~8 points. Static context is informative, but not sufficient alone.

Static + time only (7 features) — AUROC 0.679

Even without a single vital sign, just knowing ICU length-of-stay, hour, and patient demographics reaches AUROC 0.68. ICULOS alone is remarkably predictive — but the model saturates quickly.

Removing ICULOS and HospAdmTime — AUROC 0.759

Dropping the strongest static features barely hurts (0.765 → 0.759). This is the crucial result: the model does not depend on ICU length-of-stay to perform well. The dynamic vitals are sufficient.

Takeaway: You cannot remove dynamic vitals — AUROC collapses to 0.684. You can remove the strongest static feature (ICULOS) and lose only ~0.6% AUROC. This proves the temporal feature engineering delivers real, non-redundant value.

13. Conclusion & Future Work

Key Findings

  1. Feature engineering beats algorithm choice. Three classical models (LR, RF, HGB) plateau around AUROC 0.70–0.74 on raw features. Temporal XGBoost on engineered features reaches 0.80.
  2. Dynamic vitals carry the signal. SHAP shows 57.5% of model attribution comes from lag / trend / rolling features — not static demographics.
  3. The AUPRC gain is meaningful. Baselines reach 0.080–0.088 on AUPRC; the temporal XGBoost reaches 0.112 / 0.115 — a roughly 1.3× improvement on the metric that matters most under imbalance, and ~5× better than random.
  4. The model is auditable. Per-patient SHAP explanations exist for every prediction, making clinical review practical.
  5. Leakage was eliminated. Strict patient-wise splits and train-only imputation mean the reported metrics are honest.

Limitations

  • 27 lab features were dropped due to >80% missingness. A real ICU with these values available could improve accuracy further.
  • Single-dataset validation. The PhysioNet cohort is US-only; cross-hospital generalisation is not tested.
  • Probabilities are rank-correct but not calibrated. The Brier scores (0.138 / 0.145) indicate reasonable sharpness, but an isotonic calibration wrapper would be a next step for clinical deployment.

Future Work

  • Sequence models. An LSTM or Transformer over the full hourly sequence could capture long-range dependencies better than fixed lag windows. A preliminary LSTM/GRU exploration showed a 0.37 AUROC gap when proper time-horizon framing was applied — quantified in the project's future_work/ folder.
  • Two-stage imputation. Use KNN imputation on lab values (retaining them) rather than dropping the columns entirely.
  • Calibration. Wrap the XGBoost output in isotonic regression to produce clinically meaningful probabilities.
  • Prospective validation. The ultimate test is deployment in a live ICU with real-time scoring.
